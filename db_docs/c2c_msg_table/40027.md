# 字段 `40027` — 本地会话 ID

| 属性 | 值 |
|------|-----|
| 字段编号 | 40027 |
| 类型 | INTEGER |
| 所属表 | c2c_msg_table |
| 主键 | — |
| 置信度 | ✅ 高（统计规律强 + 全表 5 个索引均以 40027 为前导列，直接验证其会话分区键地位） |

## 含义

**客户端为每个私聊联系人分配的本地递增整数编号**：值从 1 开始，共 560 个唯一值对应 560 个私聊会话（联系人）。同一会话（40030 相同）的所有消息共享同一个 40027 值，与消息方向无关。可理解为客户端本地维护的「联系人槽位编号」或「会话表外键」。

## 取值说明

| 取值范围 | 说明 |
|---------|------|
| `1` ~ `561`（缺 537） | 本地递增编号，每个联系人唯一分配一个值 |

## 统计特征

| 特征 | 结果 |
|------|------|
| 总行数 | 1,318,588 |
| NULL 行数 | 0 |
| 不重复值数 | 560 |
| 值域 | 1 ~ 561 |
| 连续性 | 几乎连续，仅 536→538 存在一处跳跃（537 缺失，推测为已删除联系人） |

## 对应关系

- 每个非零 QQ（40030）严格对应唯一一个 40027 值
- 少量 40027 值被 2 个 QQ 共享，均来自 QQ=0 的系统消息（29 个系统 UID 共用了正常联系人的编号）
- 与消息方向（40013）无关，收发消息均使用相同的 40027

## 索引验证

`c2c_msg_table` 共有 5 个索引，**全部**以 `40027` 为第一列：

| 索引 | 类型 | 字段组合 |
|------|------|----------|
| `idx40027_40002_40005` | **UNIQUE** | `(40027, 40002, 40005)` |
| `idx40011_40012_40027` | 普通 | `(40011, 40012, 40027)` |
| `idx40027_40003` | 普通 | `(40027, 40003)` |
| `idx40027_40050` | 普通 | `(40027, 40050)` |
| `idx40027_40058` | 普通 | `(40027, 40058)` |

这直接证明 40027 是全表的会话分区键：所有查询先按会话过滤，再在会话内做排序/范围查询。

## 说明

- 值 537 缺失（536 直接跳到 538），推测对应一个已被删除的联系人
- 此字段可作为会话维度的分组键，等效于 `GROUP BY "40030"` 但代价更低（整数比较 vs 字符串比较）
