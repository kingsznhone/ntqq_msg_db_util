# 字段 40900 — 引用消息序列化快照

## 字段属性

| 属性 | 值 |
|------|----|
| 字段编号 | 40900 |
| 数据类型 | BLOB |
| 是否主键 | 否 |
| 置信度 | 🔍 中 |

## 含义说明

40900 存储的是**被引用/被回应消息的序列化快照**，采用与主表相同字段编号体系的嵌套 protobuf 格式。

- 仅在需要展示"上下文引用"的消息类型中有值（reaction、引用回复、图片等）
- BLOB 本身是一段 repeated protobuf 序列，每个子项对应一条被引用消息的字段副本
- 用于保存引用、回应或转发场景的上下文，使读取端可以直接取得部分关联消息信息

## 取值说明

| 取值 | 含义 |
|------|------|
| NULL | 普通消息，无引用上下文 |
| `a2 fc 13 00`（4字节） | 空快照占位符（有字段但无子消息数据） |
| 变长 BLOB | 含一条或多条被引用消息的序列化快照 |

## BLOB 结构

### 开头标志

所有非空 BLOB 均以 `a2 fc 13` 开头，对应 protobuf tag：字段号 40900、wire type 2（length-delimited）。BLOB 本身就是该字段的 repeated 编码内容。

### 子消息字段体系

内部子消息的字段编号与主表（`c2c_msg_table`）完全一致（如 40001、40011、40013、40020 等），即子消息是**主表记录的部分字段快照**。

### 空占位符

`a2 fc 13 00` 出现于多种消息类型（40011=2/3/5/11/17），代表字段存在但子消息列表为空。

## 各消息类型内容观察

### 40011=9（表情回应）

- 长度集中在 380~430 字节，结构较统一
- 内容中可识别两个 NT UID（`u_` 前缀），分别属于 Reaction 参与者和关联消息上下文

### 40011=8

- 长度变化大（数百至数万字节）
- 内容中可见 MD5 哈希字符串、UUID 格式字符串、XML 片段（`<?xml version="1.0"...`）
- 内容形态支持其为引用消息的完整或近完整快照（含媒体元数据）

## 不确定因素

- 未全量解析 protobuf 子字段，无法确认子消息字段的完整映射关系
- 未确认是完整消息体副本还是仅存部分字段
- `a2 fc 13 00` 出现原因（为何某些消息有空占位而非 NULL）尚不明确

## 关联字段

| 字段 | 关系 |
|------|------|
| 40011 | 消息类型；决定 40900 是否有值及内容结构 |
| 40800 | 消息体（protobuf）；40900 子消息可能包含被引用消息的 40800 内容 |
| 40020 | 发送者 NT UID；在 40900 子消息中可见 |

## 使用边界

- 40900 内部字段不是主表的完整副本，读取时应按“缓存快照”处理。
- 具体场景需结合 `40011`、`40012` 和嵌套字段判断，不能仅凭 40900 存在就断言为引用。
