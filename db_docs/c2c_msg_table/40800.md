# 字段 `40800` — 消息体（Protobuf）

## 字段属性

| 属性 | 值 |
|------|-----|

| 数据类型 | BLOB |
| 是否主键 | 否 |
| 置信度 | ✅ 高 |

## 含义说明

`40800` 存储消息的**实际内容主体**，编码为 Protobuf（wire format）。
本列是整张表最核心的字段，文本、图片、文件、语音、位置、合并转发、通话记录等所有消息内容均序列化于此。

- 全表 1,318,588 行中，1,318,117 行非 NULL（约 99.96%）
- NULL 仅出现于部分 `40011=0/1` 的无效/已删除消息中

## Protobuf 结构（逆向还原）

### 外层包装：`MsgBody`

```
message MsgBody {
  repeated MsgContent content = 40800;
}
```

- 顶层只有 `field 40800`（wire key `40800-2`）
- **1,240,057** 行解码为单个 `dict`（content=1 条），**78,060** 行为 `list`（content≥2 条，repeated）
- 另有 **28** 行以 `wire key 40800-1`（varint encoding）出现，推测为旧协议兼容字段

#### 多段消息（图文混排，78,060 行）

原始报告将此部分标注为"内层解码失败"，实为**误报**。全量验证结果：78,060 行中的 list item 全部是已解码的 `dict`（MsgContent），**0 条 bytes item，0 条解码失败**。真实含义是：该行消息由多个 `MsgContent` 段组成，proto repeated 语义。

### 位置消息（40011=7，45851–45863）

> ⚠️ **重要修正（2026-05-13 全量验证）**：
> 本数据库中 `40011=7` 的 876 条记录，经逐条解码确认，**全部为「带位置 tag 的短视频」**（`content_type=5`，`45402` 为视频文件路径），

> **关于 177 行「解码失败」（2026-05-13 修正）**：
> 原始报告中 177 行（20.2%）proto 解码失败，根因已定位：这些行使用新版 CDN 结构，`45504`（cdn_path）缺席，
> 改由 **`45510`** 携带第二 CDN token（与 `45503` 同格式的 base64url 字符串）。

> 修正 `f45510` 为 `string` 后，全 876 行解码 100% 成功，`content_type` 全为 `5`，无一例外。

#### 49154 枚举值详解

全库仅出现 **2 个枚举值**，100% 为可打印 ASCII，全量 UTF-8 解码无失败：

| 值 | 长度 | 出现次数 | 时间范围 | 含义 |
|----|------|---------|---------|------|
| `"1"` | 1 字节 | 19,956 | 2024-11 ~ 2025-11 | NT 早期客户端版本标识 |
| `"nt_1"` | 4 字节 | 10,037 | 2025-11 起（2025-12 完全切换）| NT 更新版客户端版本标识 |

**关键验证**：
- **100%** 出现在 `40060=0`（NT 新协议）消息中，旧协议（40060=1）中从不出现
- **97–98%** 出现在 `40013=1`（发出）消息中（少量接收消息中出现推测为服务端回写）
- **时间切换**：2025-11 为过渡期，2025-12 起 `"1"` 完全消失、仅剩 `"nt_1"`
- 同一消息的多段 `MsgContent` 中，49154 值**恒相同**（2,387 条多段消息验证，0 例不一致）
