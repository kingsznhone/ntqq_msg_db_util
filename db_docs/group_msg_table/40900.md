# 字段 `40900` — 引用/转发缓存 Protobuf

## 结论

`40900` 是嵌套的消息快照缓存，不是随机 BLOB。它保存一条或多条部分消息记录，并复用主表字段以及 `40800/40801/40802` 等消息结构。

当前可以确定其 Protobuf 结构和全量可解析性；在不同 `40011` 场景中，它可能承担引用、Reaction、旧协议转发或其他上下文缓存，不能用单一业务名称覆盖所有记录。

## 统计

基于 `540,018` 行：

- NULL：`503,893` 行；
- 非 NULL：`36,125` 行；
- group 专用强类型解析成功：`36,125` 行；
- 非 NULL 成功率：`100%`。

## 外层结构

```text
CacheBody.content = 40900 (repeated CacheMessage)
```

对应 schema 和解析器：

- `msgdb/proto/group_40900.proto`
- `msgdb/proto/group_40900_parser.py`

`40900` 可以重复出现，单条记录也可能包含多个缓存消息。

## 嵌套字段

| 字段 | 当前处理 | 说明 |
|---:|---|---|
| `40800` | repeated bytes | 嵌套消息体；通常递归使用共享 `40800` parser |
| `40801` | repeated bytes | 摘要/状态快照；常见 `41501`、`41502` |
| `40802` | repeated bytes | 另一类摘要/扩展快照 |
| `41999` | bytes | 复杂递归扩展，暂保留原始 bytes |
| `49082` | int32 | 未命名扩展字段 |

多态字段保留为 bytes 是有意设计：不同场景可能使用不同的子消息，不能为了让 schema 看起来完整而固定成单一类型。

| `40011` | 行数 | 常见场景 |

主要组合为 `40011=9,40012=33`、`40011=8,40012=0` 和 `40011=5,40012=4`。

## 解析规则

1. 优先使用 `CacheBody` 强类型解析；
2. 对 `40800/40801/40802` 的 bytes 子项按各自 parser 递归解析；
3. 失败时回退到 `msgdb/proto/wire.py`；
4. 保留未知字段、多态 payload 和原始 bytes；
5. 解析状态区分 `typed`、`wire_fallback`、`invalid`、`null`。

## 研究边界

当前不确定：

- `40900` 在各个 `40011` 类型下的精确产品用途；
- `40801`、`40802` 的摘要业务语义；
- `41999` 内部字段含义；
- 缓存是完整消息副本还是按场景截取的部分字段。
