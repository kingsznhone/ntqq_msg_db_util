# 字段 `40900` — 引用/转发缓存（Protobuf）

## 字段属性

| 属性 | 值 |
|------|-----|
| 字段编号 | 40900 |
| 数据类型 | BLOB |
| 所属表 | `group_msg_table` |
| 是否主键 | 否 |
| 置信度 | ✅ 高（结构）/ 🔍 中（具体用途） |

## 含义

`40900` 是结构化的 Protobuf 缓存字段，用于保存引用消息、转发上下文或其他消息快照。它不是随机 BLOB。

其内部字段大量复用 `group_msg_table` 的主表字段和 `40800` 消息体字段，因此可以看作一组嵌套的消息记录快照。

- 强类型成功率：`100%`。

## 外层结构

统一 group 超集定义位于：

- `msgdb/proto/40900.proto`
- `msgdb/proto/group_40900_pb2.py`
- `msgdb/proto/group_40900_parser.py`

外层结构：

```protobuf
message CacheBody {
  repeated CacheMessage content = 40900;
}
```

`40900` 可以重复出现，且部分记录包含多个缓存消息。

## 嵌套消息字段

第一版超集将多态嵌套字段暂存为 `repeated bytes`，保证所有样本无损读取：

| 字段号 | 第一版类型 | 初步含义 |
|-------:|------------|----------|
| `40800` | repeated bytes | 嵌套消息体快照，内部通常包含 `45001`、`45002`、文本或媒体字段 |
| `40801` | repeated bytes | 消息摘要/状态快照，内部常见 `41501`、`41502` 等字段 |
| `40802` | repeated bytes | 另一类消息摘要/状态快照 |
| `41999` | bytes | 复杂扩展结构 |
| `49082` | int32 | 未知扩展字段 |

bbpb 探测表明：

- `40800` 内部可包含标准 group 消息体；
- `40801` 可重复，内部包含 `41501`、`41502` 以及多个状态字段；
- `40802` 也可能重复；
- `41999` 是复杂递归结构，包含多个未命名子字段。

当前将这些字段保留为 bytes，而不是错误地固定为单一子消息类型。

## 解码策略

`msgdb/proto/group_40900_parser.py` 的 `parse_40900` 提供：

1. `CacheBody` 强类型解析；
2. 失败时回退到 `msgdb/proto/wire.py`；
3. 返回 `typed`、`wire_fallback`、`invalid` 或 `null` 状态；
4. 保留多态字段原始 bytes；
5. 后续可对 `40800/40801/40802/41999` 分别递归解析。

## 研究边界

当前可以确认 `40900` 的 Protobuf 结构和消息快照性质，但仍未完全确认：

- `40900` 在不同 `40011` 类型下具体表示引用、Reaction 还是转发缓存；
- `40801`、`40802` 各自的摘要业务语义；
- `41999` 内部复杂结构各字段意义；
- 某些字段是否为主表字段的完整快照还是局部缓存。
