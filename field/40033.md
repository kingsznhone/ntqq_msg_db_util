# 字段 `40033` — 发送者 QQ

| 属性 | 值 |
|------|-----|
| 字段编号 | 40033 |
| 类型 | INTEGER |
| 所属表 | c2c_msg_table |
| 主键 | — |
| 置信度 | ✅ 高（与 40030/40013 联动验证，吻合率 >99.8%） |

## 含义

**消息发送者 QQ 号**：记录实际发送该条消息的 QQ 号。随消息方向（40013）变化：收到消息时为对方 QQ（= 40030），发出消息时为本人 QQ。

## 取值说明

| 特征 | 结果 |
|------|------|
| NULL 行数 | 约 2,193 行（0.17%，旧数据缺字段） |
| 唯一值数 | 555 |
| 40033 = owner QQ 的行数 | 685,250（51.97%，本人发出） |
| 40033 ≠ owner QQ 的行数 | 633,338（48.03%，他人发出） |

## 取值规律

| 40013 值 | 40033 期望值 | 实际吻合率 |
|---------|------------|---------|
| `0`（收到） | = 40030（对方 QQ） | 99.77% |
| `1`（发出） | = owner QQ | 99.89% |
| `2`（发出特殊） | = owner QQ | 100.00% |
| `3`（系统消息） | NULL | 100%（40 行全为 NULL） |
| `4`/`5`（极少特殊） | = owner QQ | 100% |

不吻合的行（约 2,193 行）均为 `40033 = NULL`，集中于特定联系人的旧消息，推测为早期协议迁移时字段缺失所致。

## 关联字段

| 字段 | 关系 |
|------|------|
| `40013` | 消息方向；决定 40033 的取值（本人 QQ 或联系人 QQ） |
| `40030` | 会话对象 QQ；40013=0 时 40033 = 40030 |
| `40020` | 发送者 NT UID；与 40033 严格一一对应 |
| `40093` | 发送者昵称；与 40033 对应的显示名称 |

## 验证方法

- 收到消息发送者验证：`SELECT COUNT(*) FROM c2c_msg_table WHERE 40013=0 AND 40033=40030` → 期望 ~100%
- 发出消息发送者验证：`SELECT COUNT(*) FROM c2c_msg_table WHERE 40013=1 AND 40033=<owner_qq>` → 期望 ~100%
- 与 40020 对应验证：`SELECT COUNT(DISTINCT 40033) FROM c2c_msg_table GROUP BY 40020` → 每个 NT UID 应对应唯一 QQ 号

## 说明

- 约 2,193 行 40033 = NULL，不影响主体规律，为历史数据字段缺失所致。
- 40033 唯一值 555 略少于 40030 唯一值 561，差值来自少量联系人从未在 40033 出现（如仅有系统消息的会话）。
