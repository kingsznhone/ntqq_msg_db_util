# 字段 `40006` — serverSeq（服务端操作序号）

| 属性 | 值 |
|------|-----|
| 字段编号 | 40006 |
| 类型 | INTEGER |
| 所属表 | c2c_msg_table |
| 主键 | ✗ |
| 置信度 | ✅ 高（结构特征和时序规律强，但语义名称无法通过协议文档直接验证） |

## 含义

**服务端为消息/操作分配的 64 位复合 ID**：高 8 位为版本/类型前缀（几乎全为 `0x01`），低 32 位为服务端序号。此字段仅在 NT 新协议消息中出现（旧历史迁移数据为 `0`）。同一批量操作（如一次多会话广播）可共享同一个值。

## 取值说明

| 值 | 含义 | 说明 |
|----|------|------|
| `0` | 未填充 | 旧协议历史迁移记录，或该字段对此消息不适用（占全表 92.1%） |
| `0x01000000XXXXXXXX` | 服务端序号 | 高字节 `0x01` 为版本前缀，低 32 位为实际序号 |
| `0x02000000XXXXXXXX` | 服务端序号（v2） | 极少量，高字节 `0x02`，可能为更新版本 |

## 特征

| 特征 | 结果 |
|------|------|
| 总行数 | 1,318,588 |
| 不重复值数 | 104,009（7.89%） |
| NULL 行数 | 0 |
| 零值行数 | 1,214,538（92.11%） |
| 值域 | `0x0000000000000000` ～ `0x02000000003A00A6` |
| 时序单调性（按 40006 升序） | 99.8%（与时间单调递增，即 40006 越大越新） |
| 与 40001 Pearson 相关系数 | **-0.9592**（强负相关：40001 递增，40006 递减） |
| 会话内恒定的会话比例 | 88.4%（496/561，这些会话 40006 全为 0） |

## 结构解析

非零值的十六进制结构：

```
0x 01 000000 XXXXXXXX
   ↑  ↑      ↑
   │  │      └── 低 32 位：服务端实际序号（随时间单调递增）
   │  └────────── 中间 3 字节：全为 0x00（保留或填充）
   └───────────── 高 8 位：版本/类型前缀（几乎全为 0x01）
```

## 时序特性

- 40006 与时间正相关（按 40006 升序后，40050 单调不减比例 99.8%）
- 40006 与 40001 强负相关（-0.9592）：40001 是递增 ID，40006 递减（越旧消息值越大，越新消息值越小）
- 换言之：40006 在数值空间中"从大到小"随时间分配，与 40003（全局倒序序号）行为类似

## 批量操作特征

同一 40006 值可对应多个不同会话（40030），但发送者（40033）相同，时间极为接近（同秒内），消息方向为特殊状态（40013=5）。这表明 40006 是**服务端事务/批次 ID**，一次批量操作（如多会话同步通知）使用同一个值。

示例：`0x010000005638E1D7` 出现 6 次，分属 6 个不同会话，发送时间均为 2025-04-24 02:51 ～ 02:54，方向均为 5。

## 关联字段

| 字段 | 关系 |
|------|------|
| `40001` | msg_uid，与 40006 强负相关（-0.9592）；40001 递增，40006 递减 |
| `40003` | 全局倒序序号，行为特性类似（均随时间单调，旧数据为 0） |
| `40013` | 消息方向；方向=5 的特殊消息频繁出现跨会话相同 40006 |
| `40030` | 私聊对方 QQ；同一 40006 可横跨多个不同 40030 |
| `40050` | 发送时间戳；与 40006 正相关（99.8% 单调） |

## 验证方法

1. 在 NT 协议抓包中查找 `serverSeq` 或 `opId` 字段，对比数值结构
2. 观察 40013=5 的批量操作记录，确认同批次消息是否共享 40006
3. 对比 40006 与 40003 的值域和单调方向，验证是否属于同一序号空间

## 说明

- 零值（0）不代表"无效"，仅表示旧协议历史数据未填充该字段
- 大多数会话（历史消息多的会话）40006 全为 0，这与 NT 新协议上线时间吻合
- `0x02` 高字节前缀的值极少量（仅个位数），可能是协议升级的实验版本
